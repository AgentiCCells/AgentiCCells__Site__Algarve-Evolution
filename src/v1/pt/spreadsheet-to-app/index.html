Da folha de cálculo à aplicação

Traga uma folha de cálculo do seu trabalho, saia com uma aplicação.

Um programa de sessões que nos foi proposto pelo SGit Newsroom a 31 de outubro de 2026. Uma premissa: vamos transformar a sua folha de cálculo numa aplicação. Traria as pessoas que mais queremos alcançar: quem trabalha em empresas locais e já gere parte do trabalho em folhas de cálculo, tem curiosidade pela IA e quer percebê-la fazendo algo útil.

Experimente já, no seu navegadorLer as cinco instruções

Fonte: SGit Newsroom

Os dois únicos requisitos

  1. Uma conta num modelo que consiga construir uma aplicação: Lovable, Claude, ChatGPT, Mistral ou outro.
  2. Uma folha de cálculo ou um documento do seu trabalho, com dados fictícios: com a mesma forma que o verdadeiro, suficientemente próximo para ser útil e seguro para publicar.

Mais nada. Os dados fictícios deixam de fora tudo o que é confidencial, por isso nada precisa de ser protegido, e permitem publicar e partilhar a aplicação no próprio dia, que é onde se aprende.

Traga um portátil e um carregador. Os planos gratuitos podem servir; os créditos do evento ajudam.

Sem página em branco

A maior parte dos workshops encrava no mesmo momento: alguém pergunta que problema quer resolver e a sala fica em silêncio. Aqui, as pessoas chegam com o problema já escrito, numa folha de cálculo que usam todas as semanas. Para quem chegar sem nenhuma, há cinco exemplos prontos, inventados e publicáveis. Escolha um, ou traga o seu, e veja as cinco instruções transformá-lo numa aplicação.

Esta página constrói a aplicação com regras simples no seu navegador, não com um modelo de IA, para que veja em segundos o tipo de aplicação que as cinco instruções produzem. No dia, cada pessoa constrói a sua com o modelo que escolher.

Pagar por utilização, simulado: cada ação na ferramenta custa alguns cêntimos de crédito (veja o contador em baixo, à esquerda). Nada é cobrado; o crédito fica só neste navegador.

O método

Cinco instruções, por ordem

Use qualquer modelo que consiga construir e publicar uma pequena aplicação web: Lovable, Claude, ChatGPT, Mistral ou outro. Cole a sua folha de cálculo (só dados fictícios) ou um dos exemplos com a primeira instrução e depois envie as outras uma de cada vez, usando a aplicação entre cada uma.

  1. 1

    Instrução 1

    Uma lista onde posso pesquisar

    Aqui está a minha folha de cálculo, com dados fictícios. Constrói uma aplicação web de uma só página que a mostre como uma lista onde posso pesquisar e filtrar. Guarda os dados no navegador: sem base de dados, sem login, sem servidor. Mostra primeiro as colunas mais importantes.
  2. 2

    Instrução 2

    Acrescentar e alterar linhas

    Acrescenta um formulário para adicionar uma linha e para editar ou apagar uma. Guarda tudo no armazenamento local do navegador e acrescenta botões para exportar os dados em CSV e para os voltar a importar.
  3. 3

    Instrução 3

    A vista que mais uso

    A vista que mais uso é: [as tarefas de hoje / o que encomendar / as faturas por pagar / as aulas desta semana / os membros que não pagaram]. Faz dela o primeiro ecrã, com os itens mais importantes primeiro, e deixa-me marcar cada um como feito.
  4. 4

    Instrução 4

    Lembrar cada ronda

    Sempre que termino uma ronda (um dia, uma encomenda, uma sessão), guarda um pequeno registo datado do que fiz, do que saltei e uma nota. Mostra o histórico como uma lista, do mais recente para o mais antigo.
  5. 5

    Instrução 5

    Publicar e dizer o que é

    Publica-a para que outra pessoa a possa abrir. Escreve uma pequena secção "sobre": o que a aplicação faz, onde ficam guardados os dados e o que ainda não faz.

Depois das cinco: use-a a sério e volte com o que falhou ou o que faltou. Essa é a instrução seguinte.

Onde ficam as aplicações

Três formas de publicar

Um programa pode usar as três.

  1. A

    A ferramenta de cada pessoa

    O Lovable, um artifact do Claude ou um canvas do ChatGPT podem publicar uma pequena aplicação com um link.

  2. B

    Uma organização GitHub para o programa

    Teríamos uma organização GitHub com um repositório modelo; cada participante recebe um repositório feito a partir dele, publicado com o GitHub Pages. Todos partem da mesma base e cada aplicação tem um histórico.

  3. C

    Uma pequena equipa que as muda

    Os participantes publicam a partir da sua ferramenta, partilham o link e uma equipa de fornecedores da região muda a aplicação para a organização, durante a tarde. É a primeira amostra dos serviços de aldeia (villager services), no próprio dia.

Depois do dia

  • Cada aplicação tem uma página, com a autorização de quem a fez.
  • Um acompanhamento no prazo de uma semana: o que a aplicação precisa para ser usada por outros e quem na região o pode fazer.

Muitas destas aplicações vão falhar mais tarde, quando mais pessoas precisarem delas e quem as construiu tiver o seu emprego. É aí que entram os fornecedores da região, e é esse o mercado que estas sessões criam.

O que isto não afirma

  • É uma proposta, com um evento simulado. Ainda não se realizou nenhuma sessão e nada nela está acordado.
  • Todos os exemplos, pessoas e números do pacote são inventados.
  • A aplicação convertida foi feita para a proposta, para mostrar o que as cinco instruções produzem; a de cada participante será diferente. Tal como as aplicações feitas pela ferramenta desta página.
  • Os modelos mudam. As instruções foram escritas para qualquer modelo que consiga construir e publicar uma pequena aplicação web.
  • O autor da proposta declarou um interesse: a The Cyber Boardroom vai aderir à Algarve Evolution e oferece serviços de aldeia (villager services).
