How the integration works

  1. 1 Now · Working

    Read from the public website

    The site reads what our Odoo already publishes: the sitemap, one calendar file per event and the blog feeds. No password, no API key, public pages only, one request at a time. It keeps names, dates, places and links, never descriptions, e-mail addresses or telephone numbers.

  2. 2 Next · Proposal

    Read with our own API key

    With a read-only API key created in our Odoo and kept as a secret in our own build, the site could read more of what Odoo holds: event seats and status, programmes, and the talent map from our contacts, listing only those who have said yes. The key stays with us; the site never stores data of its own.

  3. 3 Later · Proposal

    Write back to Odoo

    What people do on the site could land in Odoo, where our team already works: a need posted on the talent map as a lead or a ticket, a consent answer as a tag on the contact, and pay-per-use credit in Odoo’s own accounts. Nothing is written to our Odoo today.
