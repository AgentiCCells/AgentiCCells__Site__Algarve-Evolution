In one slide

Integrate, do not replace

  • Two worlds. The official Odoo (algarveevolution.pt, Odoo 19 Enterprise, Odoo 20 planned) is the mature system; a throwaway Odoo 19 Community is where we try things fast.
  • Two feeds. A public feed holds only published records; a private feed holds the rest, published only encrypted and opened with an access key.
  • Writes are planned, then applied. Reviewed and signed by a person, checked against a written policy, applied by a broker that keeps a record.
  • Odoo 20 fits. Its agents and MCP server map onto the same model: each agent gets a behaviour policy; its exposed tools are its grant.
  • What we ask of you: the API on your plan, a read-only user or a staging copy, where the data lives today, and how proven experiments should land.

The two feeds

Pages never talk to Odoo: they read two files

Public feedPrivate feed
HoldsRecords marked published; people only with consentEverything, including notes, contacts, participants, jury scores
ServedA plain JSON file with the siteEncrypted (AES-256-GCM, PBKDF2-SHA256, 200,000 iterations); opened in the browser with an access key that never travels
Read byAnyoneThe Algarve Evolution team
Written byThe exporter, over the Odoo 19 JSON-2 API (/json/2/<model>/search_read), as a dedicated read-only user with its own API key. A checker refuses any export that would leak a private field, an e-mail address or an unconsented person.

The official Odoo is read today without credentials: sitemap, one calendar file per event, blog feeds. Names, dates, places and links only, each linking back.

Plan, then apply

Nothing reaches Odoo without a signed, checked plan

1 SnapshotRead the records the change touches, as they are now
2 PlanA hub page or a cell writes the proposed Odoo calls into the plan queue
3 Policy checkAllowed models and methods only; no deletes, no users or access rights
4 Signed approvalA person approves each item and signs the plan with their own key
5 Broker appliesChecks signature, reviewer, policy and snapshot; writes through the JSON-2 API
6 RecordPlan hash, reviewer and each change kept in a log that outlives any chat

Running against our experimentation Odoo and tested end to end on 16 November 2026, every refusal included. Today nothing writes to Algarve Evolution's Odoo.

The broker's guarantees

What the broker refuses, by design

Before it writes

  • A signature that does not verify
  • A reviewer whose key is not on the allow list (empty until a person adds one)
  • Any delete, or anything on users, groups or access rights
  • A record that changed since its snapshot

Where and how

  • Any host but the experimentation Odoo; never algarveevolution.pt
  • The same plan twice
  • Writes as a plan-broker user: create and write, never delete
  • A dry run unless told --apply; a log line for every change

Odoo 20 MCP server

The exposed tools are the agent's grant

By default, read only

  • Get Fields, Get Models
  • Retrieve initial context
  • Search, Read group

Every other tool must be exposed one by one ("Available in MCP"), optionally marked read-only so it runs without approval.

Access you control

  • OAuth (recommended), approved clients only, access that expires
  • Or an API key with MCP scope and an expiry
  • Revoke by deleting the key
  • Claude Code connects with claude mcp add --transport http

Source: Odoo 20.0 documentation, AI agents and AI MCP server, read 16 November 2026. Not yet tested by us on a real instance.

Security and data

Algarve Evolution's data stays in Algarve Evolution's systems

Keys

Created by you, for a dedicated user, kept in your build secrets. Never in chat or a repository.

Least access

Read-only for feeds; create and write without delete for the broker; nothing on users or access rights.

Consent

People appear in a public feed only with recorded consent; withheld records are counted, never shown.

Signed writes

A person's signed approval, a policy check and a snapshot comparison before anything is applied.

Throwaway

The experimentation Odoo holds no real person's data and is rebuilt from one script.

Unlisted

The prototype is not indexed by search engines and is linked from nowhere.
